    "Full Description": "[Impact]\n\nThe tc/tbf and tc/htb burst option is currently limited to 4\u202fGiB (UINT_MAX for a 32-bit unsigned int). However, the kernel internally represents burst as \u201ctime at the configured rate,\u201d which allows for bursts exceeding 4\u202fGiB at high speeds. Due to this limitation, large bursts that are valid in the kernel cannot be configured from userspace. Conversely, smaller bursts can silently overflow the internal burst time calculation, causing invalid values to be passed to the kernel without detection, potentially resulting in misconfigured queues and incorrect rate limiting.\n\n[Test plan]\n\nPrerequisites\nA system with tc (iproute2) installed\nRoot privileges\nTest interface (replace eth0 if needed)\n\n1. TBF (Token Bucket Filter)\n\n1.1 Before patch\n\nCase A: Burst >= 4GB rejected\n# tc qdisc add dev eth0 handle 10: root tbf rate 0.5mbit burst 4294967296  latency 70ms peakrate 1mbit minburst 1540\ntbf: illegal value for \"burst\": \"4294967296\"\n\nCase B: Overflow not detected\n# tc qdisc add dev eth0 handle 10: root tbf rate 1mbit burst 34375000  latency 70ms peakrate 10Gbit minburst 1540\n\n# tc qdisc show dev eth0\nqdisc tbf 10: root refcnt 9 rate 1Mbit burst 15261b peakrate 10Gbit minburst 1250b lat 275s\n\nBurst was not set correctly and it should have been flagged as burst being out of range.\n\n1.2 After the patch\n\nCase A: Burst >= 4GB supported\n# tc qdisc add dev eth0 handle 10: root tbf rate 10gbit burst 4294967296 latency 70ms peakrate 30Gbit mtu 64Kb\n\n# tc qdisc show dev eth0\nqdisc tbf 10: root refcnt 2 rate 10Gbit burst 4Gb peakrate 30Gbit minburst 65520b lat 70ms\n\nCase B: Overflow properly rejected\n# tc qdisc add dev eth0 handle 10: root tbf rate 1mbit burst 34375000  latency 70ms peakrate 10Gbit minburst 1540\ntbf: burst out of range\n\n2. HTB (Hierarchical Token Bucket)\n\n2.1 Before the patch\n\nCase A: Burst >= 4GB rejected\n# tc qdisc add dev eth0 root handle 1: htb\n# tc class add dev eth0 parent 1: classid 1:1 htb rate 10gbit ceil 10gbit burst 4gb\nIllegal \"burst\"\n\nCase B: Overflow not detected\n# tc class add dev eth0 parent 1: classid 1:1 htb rate 1mbit ceil 5mbit burst 34375000\n# tc class show dev eth0\nclass htb 1:1 root prio 0 rate 1Mbit ceil 5Mbit burst 34359738b cburst 1600b\n\nBurst was not set correctly and it should have been flagged as burst being out of range.\n\n2.2 After the patch\n\nCase A: Burst >= 4GB supported\n# tc qdisc add dev eth0 root handle 1: htb\n# tc class add dev eth0 parent 1: classid 1:1 htb rate 10gbit ceil 10gbit burst 4gb\n# tc class show dev eth0\nclass htb 1:1 root rate 10Gbit ceil 10Gbit burst 4Gb cburst 1680b\n\nCase B: Overflow properly rejected\n# tc class add dev eth0 parent 1: classid 1:1 htb rate 1mbit ceil 5mbit burst 34375000\nhtb: burst out of range\n\n[Where problems could occur]\n\nExternally, the main impact is that commands which previously caused silent overflows may now produce errors or fail. This could break scripts or automation that relied on the old behavior, though those scripts were already misbehaving due to the invalid configuration."
